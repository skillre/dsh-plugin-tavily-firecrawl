# Contributing

1. Read `AGENTS.md`.
2. Open an issue or state the behavior and compatibility target clearly.
3. Inspect the current DSH runtime contracts before implementation.
4. Keep one concern per branch and avoid unrelated dependency updates.
5. Add behavior and lifecycle tests.
6. Run `npm run check`.
7. Add a Changeset for user-visible changes.
8. Include the exact DSH versions tested and tarball/profile verification evidence in the review description.

Do not publish, tag, or alter release infrastructure as part of an ordinary feature change.
